## 2. 重构总目标

把当前 `dllmain.cpp + runtime hooks + bridge + overlay` 的混合实现，拆成**按功能独立、按职责封边、可单独验证**的模块。

本轮明确优先级不是“按技术层先拆光”，而是先按用户最关心的功能域拆：

1. 骑宠二段跳
2. 骑宠攀爬
3. 骑宠飞行 / 滑翔
4. 独立 BUFF
5. 被动强化
6. 超级技能路由 / 发包改写
7. 原生技能栏注入 / UI 展示

原则：

1. 每个功能必须有单独入口、单独状态、单独日志前缀、单独验证清单。
2. 先把“功能边界”切开，再做通用基础设施下沉。
3. 不允许继续把新功能直接堆进 `dllmain.cpp`。

## 3. 第一层模块边界（按功能域）

## 3.1 骑宠二段跳模块

建议模块：

- `src/runtime/features/mount_demon_jump_runtime.h/.cpp`

负责内容：

1. `30010110 / 30010183 / 30010184 / 30010186` 的 runtime context
2. root -> child skill 识别与记忆
3. late gate / terminal clear / tail finalize
4. `B28A00 / B2F370 / B300AC / 7DBC50 / 575D60 / B22630 / B1DB10` 相关专属逻辑

禁止再耦合的内容：

1. 不能把 BUFF、本地属性、UI 逻辑继续混进这个模块
2. 不能把通用 mounted route 和 demon jump 特例继续交叉写在同一段大函数里

验证关键词：

- `MountDemonJump`
- `MountDemonJumpPacket`
- `MountDemonJumpLate`
- `MountDemonJumpProbe`
- `B28A00`

## 3.2 骑宠攀爬模块

## 4. 第二层模块边界（横向基础设施）

在第一层功能域拆开后，再统一下沉下面这些横向能力：

1. `runtime_context`
   - 聚合每个功能域状态对象
2. `hook_registry`
   - 只负责安装 / 卸载 / 降级
3. `path_service`
   - 统一 skill/config/cache/runtime path

   - 统一 marker / hash / module path / runtime evidence 输出

   - 统一关键日志 tag 常量，避免改造时把 tag 改乱

## 5. 服务端同步重构目标

客户端拆模块后，服务端也要对应收口，否则功能还是会跨端耦合。

服务端建议目标模块：

1. `SuperSkillRegistry`
   - 只负责定义解析与热重载
2. `MountedSkillService`
   - 只负责 mountItemId / behaviorSkillId / allowMountedFlight
3. `IndependentBuffService`
   - 只负责独立 BUFF carrier / statBonuses / cancel 语义
4. `PassiveBonusService`
   - 只负责被动加成汇总
5. `SuperSkillSpService`
   - 只负责 carrier SP、消耗、重置、回退

注意：

- `G:\code\dasheng099` 当前不是 git 仓库，真正服务端重构前应先单独建立版本管理基线。

## 6. 本轮建议的重构顺序

严格按这个顺序：

1. 先抽 `mount_demon_jump_runtime`
2. 再抽 `mount_climb_gate_runtime`
3. 再抽 `mount_flight_runtime`
4. 再抽 `independent_buff_*`
5. 再抽 `passive_bonus_runtime`
6. 再抽 `skill_route_policy`
7. 最后才继续瘦身 `dllmain.cpp`

原因：

1. 这是用户最敏感、最常改、最容易回归的功能域
2. 先按功能拆，回归面更清楚
3. 等功能域稳定后，再做通用层下沉，风险最低

---

## 7. 每个模块的验收要求

每拆出一个模块，必须同时满足：

1. build marker 不变
2. 构建 DLL 与运行 DLL 哈希可对齐
3. 原日志 tag 仍能检索
4. 功能域专属日志链闭环
5. 对应手工回归项通过

例如：

### 骑宠二段跳模块

1. `↑↑`
2. `←← / →→`
3. 按住跳跃滑翔
4. 放开跳跃退出滑翔

### 骑宠攀爬模块

1. ladder
2. rope
3. climb 后再起跳

### 独立 BUFF 模块

1. GIVE_BUFF
2. CANCEL_BUFF
3. overlay icon
4. 本地属性持续存在
5. 刷新时不被旧 cancel 误伤

---

## 8. 这次重构最重要的禁止事项

1. 不要一边拆结构，一边顺手改玩法逻辑。
2. 不要把多个功能域放进同一个“runtime helper”大文件里。
3. 不要为了“看起来整洁”删除现有关键日志。
4. 不要把 mounted demon jump、mounted climb、mounted flight 再重新混成一个大状态机文件。
5. 不要在没有 hash + marker + 日志闭环前宣称“模块拆完没问题”。

---

## 9. 一句话执行策略

先把**骑宠二段跳 / 攀爬 / 飞行 / 独立 BUFF / 被动强化 / 路由改写 / 原生技能栏注入**拆成独立功能模块，
每个模块保留原日志闭环和独立回归清单；
等功能边界稳定后，再继续下沉 `hook_registry / runtime_context / path_service`，
最终把 `dllmain.cpp` 缩成只负责启动、安装、卸载的入口文件。
