# 运行时模块总览、功能映射与关闭指南

更新时间：2026-05-11

这份文档只回答三件事：

1. 每个运行时模块做什么
2. 哪个功能用了哪个模块
3. 要关闭某个模块时，应该改哪个开关

## 1. 读取路径

运行时开关来自 `feature_switches.json`，实际路径由 `ResolveSkillConfigDir(...)` 决定。

当前部署形态下通常是：

`G:\code\mxd\Data\Plugins\SS\Skill\feature_switches.json`

兼容旧配置：

`module_switches.json`

如果 `feature_switches.json` / `module_switches.json` 都不存在，运行时默认所有开关关闭；如果配置文件存在但某个 key 没写，该 key 也默认关闭。

启动时会写日志：

`[FeatureSwitch] loaded path=... overrides=N`

## 4. 关闭方式

关闭模块的第一选择是改 `feature_switches.json`，把对应 key 设为 `false`。

如果要临时确认，可直接看日志里的 `[FeatureSwitch] key=value` 输出。

## 5. 关键开关

| key | 作用 | 关掉后 |
|---|---|---|
| `runtime.mount.doubleJumpHooks` | 骑宠二段跳总闸门 | 二段跳 runtime 主链不再装配 |
| `runtime.mount.climbGateHooks` | 骑宠攀爬门禁 | 攀爬/绳索白名单不再装配 |
| `runtime.mount.flightMappingHooks` | 骑宠飞行映射 | 飞行/soaring/family gate 不再装配 |
| `runtime.mount.movementAbilityRedHooks` | 骑宠移动 AbilityRed 绑定 | 骑宠移动相关 AbilityRed 保护不再装配 |
| `runtime.movement.setterProtectionHooks` | 全局移动 setter 防护 | setter 防护不再装配 |
| `runtime.movement.outputClampHook` | 全局移动输出 clamp | 输出 clamp 不再装配 |
| `runtime.mount.movementObservationHooks` | 骑宠移动观测 | 移动样本观测不再装配 |
| `runtime.mount.flightPhysicsSpeedHooks` | 骑宠飞行物理速度 | 飞行速度 hook 不再装配 |
| `runtime.mount.movementCapPatches` | 骑宠移动 cap patch | cap patch 不再应用 |

## 6. 恶魔跳跃彻底关闭

这里的“恶魔跳跃”指 `MountedRuntimeSkillKind_DemonJump` 这一分支，不是把整个 `MountedDoubleJump` 家族当成同一条业务线。

最小关闭：

```json
{
  "runtime.mount.doubleJumpHooks": false
}
```

如果想把相关骑宠副作用也一起收掉，再加上：

```json
{
  "runtime.mount.doubleJumpHooks": false,
  "runtime.mount.climbGateHooks": false,
  "runtime.mount.flightMappingHooks": false,
  "runtime.mount.movementAbilityRedHooks": false,
  "runtime.mount.movementObservationHooks": false,
  "runtime.mount.flightPhysicsSpeedHooks": false,
  "runtime.mount.movementCapPatches": false
}
```

如果还要把全局移动保护一并关掉，再继续关：

```json
{
  "runtime.movement.setterProtectionHooks": false,
  "runtime.movement.outputClampHook": false
}
```

## 7. 家族关系

`runtime.mount.doubleJumpHooks` 是 MountedDoubleJump family 的主闸门，`runtime_feature_runtime_hook_state.inl` 里的 `kEnableMountedDoubleJumpRuntimeHooks` 会在很多子模块里直接短路。

这意味着：

1. 主链不会装配
2. 家族内的大部分 handler 不会进入运行期
3. 如果你要关的是恶魔跳跃分支，先关这个 key
