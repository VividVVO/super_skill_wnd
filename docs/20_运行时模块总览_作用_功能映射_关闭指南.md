# 运行时模块总览、功能映射与关闭指南

更新时间：2026-05-14

这份文档只回答三件事：

1. 每个运行时模块做什么
2. 哪个功能用了哪个模块
3. 要关闭某个模块时，应该改哪个开关

## 1. 读取路径

运行时开关来自 `feature_switches.json`，实际路径由 `ResolveSkillConfigDir(...)` 决定。

当前部署形态下通常是：

`G:\code\mxd\Data\Plugins\SS\Skill\feature_switches.json`

兼容旧配置：

`module_switches.json`

如果 `feature_switches.json` / `module_switches.json` 都不存在，或者配置文件里没写某个 key，运行时都会回落到该 key 自己的编译期默认值。

启动时会写日志：

`[FeatureSwitch] loaded path=... overrides=N`

补充：

- 2026-05-13 新增了一批“原本常驻安装”的核心/UI hook 开关；为了兼容旧部署，这批新 key 的默认值是 `true`
- 2026-05-14 又补了一批 MountedDoubleJump / DemonJump 子链安装开关；这批新 key 的默认值也为 `true`
- 2026-05-14 又补了一层推荐直接使用的 `feature.*` 功能总开关；这批新 key 的默认值同样为 `true`
- `skill.runtime.enabled` 属于行为总闸：即使 hook 已经装上，也会阻止超级技能 use/release/gate allow 等核心行为
- 2026-05-14 起又解开了几条历史耦合：`runtime.core.skillNativeGateHooks` 不再顺带控制坐骑二段跳/恶魔跳跃/攀爬/飞行映射，`runtime.core.skillLevelHooks` 也不再顺带控制被动效果 hooks，`runtime.core.packetHooks` 也不再顺带卡住本地 BUFF / UI 观测 / movement ability 安装
- 2026-05-14 起人物移动和骑宠移动共用的 setter/clamp 底层 hook 也按功能总闸拆开了：`feature.playerMovement.enabled` 和 `feature.mount.movement.enabled` 可以独立控制行为，底层共享 hook 只会在任一功能启用时安装
- 2026-05-14 起当前默认构建又把原生按钮 / route-B 这条 UI 废案链降成退役路径：`runtime.ui.nativeButtonHooks`、`runtime.ui.routeBChildHooks`、`runtime.ui.skillWindowMoveHooks`、`runtime.ui.skillWindowRefreshHooks` 的编译期默认值已改成 `false`，正常自绘 UI 不再默认依赖隐藏原生按钮对象

## 4. 关闭方式

关闭模块的第一选择是改 `feature_switches.json`，把对应 key 设为 `false`。

如果要临时确认，可直接看日志里的 `[FeatureSwitch] key=value` 输出。

## 5. 推荐先看功能总开关

正常配置时，优先只改这一层：

| key | 作用 | 关掉后 |
|---|---|---|
| `feature.superSkill.enabled` | 超级技能子体系总闸 | 只会让 release / UI / independentBuff / passiveEffect 这四组一起失效，不再顺带关人物移动和骑宠功能 |
| `feature.superSkill.release.enabled` | 超级技能释放链 | use/release/classifier/native route/相关 packet rewrite 一起关闭 |
| `feature.superSkill.ui.enabled` | 超级技能 UI | overlay / SkillWnd / route-B / msg / wndproc / input 一起关闭 |
| `feature.superSkill.independentBuff.enabled` | 独立 BUFF | 本地潜能读点/显示、状态栏 BUFF 槽、cancel rewrite 一起关闭 |
| `feature.superSkill.passiveEffect.enabled` | 被动效果 | passive getter hooks、被动 attack/damage rewrite 一起关闭 |
| `feature.playerMovement.enabled` | 人物移动速度/跳跃 | 人物速度/跳跃相关 shared setter/clamp 行为关闭 |
| `feature.mount.doubleJump.enabled` | 骑宠二段跳 | 二段跳主链关闭；共享底座 / route / special move 仅在恶魔跳跃也关闭时一起收掉 |
| `feature.mount.demonJump.enabled` | 骑宠恶魔跳跃 | 恶魔跳跃主链关闭；共享底座 / route / special move 仅在二段跳也关闭时一起收掉 |
| `feature.mount.climb.enabled` | 骑宠攀爬 | 攀爬/绳索白名单一起关闭 |
| `feature.mount.flight.enabled` | 骑宠飞行放行 | 飞行映射 / soaring gate / family gate 一起关闭 |
| `feature.mount.movement.enabled` | 骑宠移动速度/跳跃/飞行速度 | override、movement observe、flight physics speed、cap patch、shared setter/clamp 的骑宠分支一起关闭 |

这层是推荐给玩家、运营和常规发布版本直接使用的。

## 6. 恶魔跳跃彻底关闭

这里的“恶魔跳跃”指 `MountedRuntimeSkillKind_DemonJump` 这一分支。
2026-05-14 这轮拆分后，它已经有自己独立的顶层总闸，不再和普通二段跳共用同一个 `feature.*` 父开关。

最小关闭：

```json
{
  "feature.mount.demonJump.enabled": false
}
```

如果只想保留恶魔跳跃总闸，但把恶魔跳跃专属子链逐段收掉，才继续用底层细开关：

```json
{
  "runtime.mount.demonJumpHooks": true,
  "runtime.mount.demonJumpCrashTraceHooks": false,
  "runtime.mount.demonJumpPacketObserveHooks": false,
  "runtime.mount.demonJumpLatePathHooks": false,
  "runtime.mount.demonJumpActionTraceHooks": false,
  "runtime.mount.demonJumpRequirementBypassHook": false,
  "runtime.mount.demonJumpContextClearHook": false
}
```

如果想把相关骑宠副作用也一起收掉，再加上：

```json
{
  "feature.mount.demonJump.enabled": false,
  "feature.mount.climb.enabled": false,
  "feature.mount.flight.enabled": false,
  "feature.mount.movement.enabled": false
}
```

如果还要把全局移动保护一并关掉，再继续关：

```json
{
  "feature.playerMovement.enabled": false
}
```

## 7. 家族关系

推荐优先关对应功能自己的总闸：
- `feature.mount.doubleJump.enabled`
- `feature.mount.demonJump.enabled`

`runtime.mount.doubleJumpHooks` 是普通二段跳主链的底层子闸门，`runtime_feature_runtime_hook_state.inl` 里的 `kEnableMountedDoubleJumpRuntimeHooks` 会在很多子模块里直接短路。

`runtime.mount.demonJumpHooks` 是恶魔跳跃专属总闸；2026-05-14 起又补了 `runtime.mount.doubleJumpBaseGateHooks` 和一组 `runtime.mount.demonJump*` 子链安装开关，用来做到“关闭的功能连 HOOK 都不要上”。

`runtime.mount.doubleJumpBaseGateHooks`、`mount.runtime.routeArm`、`packet.mountRuntime.specialMoveRewrite` 属于共享底座/共享路由层。现在它们的父条件已经改成“二段跳或恶魔跳跃任一启用即可安装”，不再被强制挂在 `feature.mount.doubleJump.enabled` 一把总闸下面。

同一天还顺手拆开了两条历史绑定关系：

1. 关 `runtime.core.skillNativeGateHooks` 时，不会再把 MountedDoubleJump / DemonJump / Climb / FlightMapping 这几组一起误关
2. 关 `runtime.core.skillLevelHooks` 时，不会再把 `runtime.core.passiveEffectHooks` 一起误关

这意味着：

1. 主链不会装配
2. 家族内的大部分 handler 不会进入运行期
3. 如果你要关普通二段跳，先关 `feature.mount.doubleJump.enabled`
4. 如果你要关恶魔跳跃，先关 `feature.mount.demonJump.enabled`

## 10. 2026-05-15 CrashCapture 稳定性补充

这轮已确认并修正两类老问题：

1. 旧实现会先 `CreateFileW(... .dmp)`，再临时 `LoadLibraryW("dbghelp.dll")`。
   如果 `dbghelp` 解析失败或 `MiniDumpWriteDump` 失败，会留下 `0` 字节空 `dmp`。

2. 只靠 `UnhandledExceptionFilter` 不够。
   对 `0xC0000409`、`0xC0000374`、`0xC0000602` 这类 fail-fast / heap-corruption 终止，进程可能来不及走到普通 unhandled filter。

当前 `src/runtime/crash_capture.cpp` 的基线：

- `dbghelp.dll` 会提前解析并缓存，优先走 `System32\\dbghelp.dll`
- dump 写失败时会删掉空 `dmp`，只保留 `txt`
- `txt` 会记录：
  - `CaptureSource`
  - `DumpAttempted / DumpWritten / DumpSize`
  - `DbgHelp / ResolveErr / CreateErr / PrimaryErr / FallbackErr`
- vectored handler 会对 `0xC0000409 / 0xC0000374 / 0xC0000602` 直接落现场
- 2026-05-15 追加：所有 `ShouldLogVectoredCandidate(...)` 命中的 first-chance 致命候选异常，都会先尝试写一份 `CaptureSource=vectored-firstchance` 的 `.txt`
  - 默认只写文本，不抢先写 dump
  - 目的是防止异常后续被游戏自己的 SEH 吃掉时，磁盘上什么都没有
  - 当前 first-chance 文本写出预算为前 `16` 次候选，避免异常风暴时刷爆磁盘
- DLL `PROCESS_ATTACH` 阶段会先做 crash capture bootstrap，不再等到后续初始化线程
- 额外接管 CRT 级 fatal 路径：
  - invalid parameter
  - purecall
  - `std::terminate`
  - `SIGABRT`

因此后续如果再出现“没有 dmp”：

1. 先看同名 `txt` 是否写出
2. 看 `CaptureSource` 是 `vectored`、`unhandled` 还是 CRT 路径
3. 看 `DbgHelp` 和各类 `Err` 字段
4. 如果连 `txt` 都没有，再判断是不是 `TerminateProcess` / 外部杀进程 / 极早期未进入插件
